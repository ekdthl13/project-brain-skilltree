# ENGINE 1 — INTENT (검색 의도 분석)

단순 키워드 분석 금지. **"왜 이걸 검색했는가?"**를 먼저 분석한다.

## 1-1. 검색자 프로파일

| 항목 | 파악 내용 |
|------|-----------|
| 검색자 유형 | 누가 찾는가? (예: 이사 앞둔 신혼부부) |
| 핵심 Pain Point | 검색 전 어떤 불편/궁금증? |
| 원하는 결과 | 글 읽고 무엇을 얻길 원하는가? |

## 1-2. 검색 단계 분류

키워드를 아래 5단계 중 하나 이상으로 분류한다.

| 단계 | 설명 | 글 방향 |
|------|------|---------|
| 탐색형 | 개념/정보 탐색 | 기초 정리 + 판단 기준 제시 |
| 비교형 | 제품/업체/옵션 비교 | 비교표 + 조건별 추천 |
| 구매직전형 | 견적/비용/업체 결정 직전 | 체크리스트 + 실수 방지 |
| 후기검증형 | 사기/후회 방지 목적 | 실제 사례 + 전/후 대비 |
| 브랜드탐색형 | 업체 신뢰도 확인 | 현장 디테일 + 전문성 |

## 1-3. 감정 상태 분석

독자의 감정을 먼저 정의한다. 도입부와 제목이 이 감정을 직접 건드려야 한다.

```
불안 / 귀찮음 / 비교 피로 / 손해 보기 싫음
실패 공포 / 전문가 부족 / 시간 부족 / 선택 장애
```

## 1-4. 클릭 욕구 분석

| 유형 | 예시 | 제목 활용 |
|------|------|-----------|
| 손해회피 | "안 보면 후회" | 경고형 제목 |
| 비교욕구 | "뭐가 더 나은가" | 비교표 제목 |
| 현실정보 | "실제 비용 공개" | 숫자형 제목 |
| 경험정보 | "직접 해보니" | 경험형 제목 |
| 실패회피 | "많이 실수하는 부분" | 반전형 제목 |

# ENGINE 2 — HOOK (클릭 유도)

## 제목 생성 — 5패턴 각 1개, 총 5개

### 패턴 A — 숫자형
```
[숫자]가지 + 핵심 키워드 + 결과
예: 중문 설치 전에 꼭 봐야 할 5가지
```

### 패턴 B — 반전형
```
흔한 생각 뒤집기
예: 중문 가격은 평수보다 이것 때문에 달라집니다
```

### 패턴 C — 공감형
```
검색자 상황 직접 명시
예: 인테리어 업체만 믿고 중문 골랐다가 후회한 이유
```

### 패턴 D — 경험형
```
직접 경험/현장형
예: 실제로 시공하면서 가장 많이 들었던 질문
```

### 패턴 E — 경고형
```
실수/함정 강조
예: 중문 견적 받을 때 이 항목 빠지면 추가금 나옵니다
```

**제목 규칙:**
- 30자 이내
- 핵심 키워드 앞쪽 배치
- 5개 중 최종 1개 추천 + 추천 이유 명시

## 썸네일 카피

제목과 별도로 썸네일용 짧은 카피 3개 생성.

- 10자 내외
- 감정 자극
- 핵심만

```
예: 추가금 주의 / 실패하는 이유 / 이거 모르고 계약함
```

## 첫 3문장 법칙

첫 3문장이 체류를 결정한다.

```
1문장: 독자 상황 직격 (Pain Point 언급)
2문장: 이 글에서 얻을 결과 구체 제시
3문장: 신뢰 근거 (경험/전문성)
```

**금지 도입부:**
```
❌ 안녕하세요
❌ 오늘은 ~에 대해 알아보겠습니다
❌ ~에 대해 설명드릴게요
❌ 많은 분들이 궁금해하는
```

# ENGINE 3 — STRUCTURE (체류시간 설계)

## 8구역 기본 구조

```
[1] 도입부 후킹        — 첫 3문장 법칙 적용
[2] 문제 공감 & 배경    — Pain Point 2~3개 열거 → 브릿지 문장
[3] 핵심 정보 블록 A    — 가장 중요한 내용 (스캔 가능한 포맷)
[4] 체류 인터럽트       — 스크롤 멈춤 장치
[5] 핵심 정보 블록 B    — 심화/비교 (판단 기준 제공)
[6] 실전 사례          — 구체적 사례 1개 이상 (수치 포함)
[7] 선택 기준/요약      — 조건부 가이드
[8] 마무리 + CTA       — 자연스러운 행동 유도
```

## ★ 글 유형별 템플릿 분기 (v4.0)

> 템플릿 상세는 **[TEMPLATES.md](./TEMPLATES.md)** 참조.
> CONTENT_PLAN.md의 "템플릿" 컬럼에 적힌 템플릿만 해당 파일에서 읽으면 된다.

### 템플릿 선택 기준 (빠른 참조)

| CONTENT_PLAN 글 유형 | 적용 템플릿 |
|---------------------|------------|
| 정보성 / 제품가이드 | A |
| 비교가이드 | B |
| 시공사례/지역 | C |
| Q&A / 노하우 | D |
| 가격가이드 | E |
| 브랜드스토리 | F |
| **시리즈 스토리** | **S** |
| 니치 | A 또는 D |

### [2] 문제 공감 상세
```
- Pain Point 1: [구체적 상황]
- Pain Point 2: [구체적 상황]
- Pain Point 3: [구체적 상황]
→ "그래서 이 글에서 ~를 정리했습니다" 브릿지
```

### [3] 핵심 정보 블록 A — 포맷 선택표

| 상황 | 추천 포맷 |
|------|-----------|
| 비교 | 표 |
| 절차 | 번호 리스트 |
| 실수 방지 | 체크리스트 |
| 후기 | 전/후 구조 |
| 선택 가이드 | 조건표 |
| FAQ | Q&A 블록 |

### [4] 체류 인터럽트 — 최소 2회 삽입

```
"근데 여기서 진짜 중요한 건..."
"많은 분들이 여기서 헷갈립니다"
"실제로 현장은 조금 다릅니다"
"이 부분 때문에 추가금이 생기는 경우가 많습니다"
"다음 항목은 많은 분들이 놓치는 부분입니다"
```

### [5] 핵심 정보 블록 B
```
- "~라면 A, ~라면 B" 조건부 가이드
- 자주 하는 실수 or 주의사항
- 선택 기준 정리
```

### [6] 실전 사례
```
- 실제 사례 1개 이상 (가능하면 수치)
- "A씨의 경우" / "실제 시공 사례에서는" 형식
- 비용, Before/After, 고객 반응 등 디테일
```

### [8] 마무리 + CTA
```
문장1: 핵심 1~2줄 요약
문장2: 다음 행동 제안 (상담/댓글/저장)
문장3: 신뢰 강화 문장
```

## 소제목 규칙

소제목만 읽어도 흐름이 파악돼야 함. **결론 암시형** 작성.

```
❌ 중문의 종류
✅ 종류가 많아서 더 헷갈리는 이유
```

## 스캔 최적화 규칙

- 3문장 이상 연속 금지
- 표/리스트 필수 1개 이상
- 강조 블록 사용
- 중간 한줄 문장 사용

## 이미지 배치 전략

이미지는 장식이 아니라 체류시간 장치다.

| 위치 | 이미지 유형 | 태그 |
|------|-------------|------|
| 도입부 직후 | 감정 공감 이미지 | `[사진: 감정 공감 이미지]` |
| 정보 블록 A | 비교표/설명 이미지 | `[사진: 비교 이미지]` |
| 사례 구간 | Before/After | `[사진: 시공 전후]` |
| CTA 직전 | 현장/신뢰 강화 | `[사진: 현장 작업]` |

- 텍스트 400~600자마다 이미지 또는 인터럽트 배치
- 실제 이미지 없을 때 `[사진: 설명]` 태그로 삽입 위치 표시

# ENGINE 4 — WRITING (본문 작성 + 인간화)

## 문체 & 톤
- 기본: 친근한 존댓말 ("~합니다", "~입니다")
- 구어체 10~20% 혼합

## 문장 리듬 규칙

반드시 섞는다:
```
짧은 문장 / 긴 문장 / 질문문 / 감정문 / 정보문 / 구어체
```

## 구어체 삽입 예시
```
솔직히 이건 진짜 중요합니다
의외로 여기서 많이 틀립니다
현장에서는 조금 달라요
```

## AI 냄새 금지 단어
```
❌ 물론 / 또한 / 더불어 / 이처럼
❌ 결론적으로 / 종합적으로 / 효과적입니다
❌ 중요합니다 (반복 사용)
❌ ~에 대해 알아보겠습니다
```

## 경험 밀도 강화

섹션별로 아래 중 **최소 3개** 포함:

| 요소 | 삽입 위치 |
|------|-----------|
| 실제 사례 | [6] 실전 사례 구간 |
| 비용 디테일 | [3] 또는 [5] 정보 블록 |
| 실패 경험 | [4] 인터럽트 또는 [5] |
| 고객 질문 | [2] 공감 구간 |
| 현장 변수 | [5] 심화 구간 |
| 비교 상황 | [3] 정보 블록 A |
| 예상 외 변수 | [4] 인터럽트 |

## 문단 길이
- 1문단 = 최대 3~4문장
- 모바일에서 스크롤 한 번에 읽히는 길이

## 분량 가이드

| 글 유형 | 권장 분량 |
|---------|-----------|
| 정보성 블로그 | 1,500 ~ 2,500자 |
| 리뷰/후기 | 1,000 ~ 1,800자 |
| 시공 사례 소개 | 800 ~ 1,500자 |
| Q&A형 | 1,000 ~ 2,000자 |

# ENGINE 5 — SEO (검색 최적화 + 스마트블록)

## 핵심 키워드 배치

| 위치 | 포함 여부 |
|------|-----------|
| 제목 | 필수 |
| 첫 문단 | 필수 |
| 소제목 1개 이상 | 필수 |
| 본문 자연 포함 | 필수 (과잉 반복 금지) |

## LSI 키워드
연관 키워드를 자연스럽게 삽입한다.
```
예: 중문 → 현관중문, 3연동, 슬라이딩도어, 아파트중문, 현관 인테리어
```

## 내부링크 전략
관련 글 유도 문구를 자연스럽게 포함.
```
"이 내용과 함께 아래 글도 많이 보십니다"
"비슷한 고민 중이시면 아래 글도 함께 보세요"
```

## 스마트블록 대응 (네이버)

"경험성"을 강화한다. 최소 3개 이상 포함:

```
실제 경험 / 현장 디테일 / 수치 정보 / 실패 사례
비교 기준 / 상황 묘사 / Before·After / 고객 반응
```

절대 금지:
```
❌ 추상적인 설명만 반복
❌ 근거 없는 통계 ("무려 80%가", "대부분의 전문가가")
❌ 뻔한 일반론
❌ 의미 없는 키워드 반복
```

## 플랫폼별 전략

### 네이버 블로그
- 경험성 최우선 — 스마트블록 대응
- `[사진: 설명]` 태그로 이미지 위치 표시
- 핵심 키워드: 제목 + 첫 문단 + 소제목에 자연 배치
- 문단 짧게, 줄바꿈 적극 활용
- 체류시간 > 키워드 밀도

### 티스토리
- SEO 구조 강화 (H2/H3 태그 활용)
- 키워드 범위 확대 (롱테일 키워드)
- 구글 SEO 동시 고려

### 브런치
- 감정선 강화, 에세이 톤
- 문장 리듬 강화 (짧은문장 + 여백)
- 이미지보다 텍스트 호흡 중심

# ENGINE 6 — CONVERSION (CTA 전환)

CTA는 **광고처럼 보이면 실패**한다.

## CTA 구조
```
1. 핵심 요약 (1~2줄)
2. 독자 행동 제안
3. 신뢰 강화
```

## CTA 유형별

| 목적 | CTA 방향 |
|------|----------|
| 댓글 유도 | 경험 공유 질문 |
| 저장 유도 | 나중 참고 제안 |
| 상담 유도 | 부담 없는 문의 |
| 링크 클릭 | 관련 글 연결 |

## 업종별 CTA 예시
```
시공업체: "견적 전에 헷갈리는 부분은 댓글 남겨주세요"
정보성:   "이 글이 도움됐다면 저장해두세요"
```

# ENGINE 7 — QUALITY CHECK (100점 자동 채점)

출력 전 **반드시** 자동 점검. 미달 시 자동 수정.
**총 100점 만점. 85점 이상이면 발행 가능. 85점 미만이면 자동 수정 후 재채점.**

## 채점 기준표

### 1. 제목 (15점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 클릭 욕구 | 5점 | 정보 갭/궁금증/손해회피 자극 |
| 핵심 키워드 배치 | 5점 | 메인 키워드가 제목 앞쪽에 포함 |
| 30자 이내 | 3점 | 모바일 검색 결과에서 잘리지 않음 |
| 5패턴 다양성 | 2점 | 5개 제목이 서로 다른 패턴 |

### 2. 도입부 (15점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 상황 직격 | 5점 | 첫 문장이 독자 Pain Point 직접 언급 |
| 결과 제시 | 5점 | 2~3문장 내에 "이 글에서 얻을 것" 명시 |
| 신뢰 근거 | 3점 | 전문성/경험/수치 근거 |
| 금지 도입부 | 2점 | "안녕하세요" 등 금지 표현 없음 |

### 3. 본문 구조 (25점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 문단 길이 | 5점 | 3~4문장 이내, 모바일 최적 |
| 표/리스트 | 5점 | 최소 1개 이상 (비교가이드는 2개 이상) |
| 체류 인터럽트 | 5점 | 최소 2회 이상 삽입 |
| 소제목 품질 | 5점 | 소제목만 읽어도 흐름 파악, 결론 암시형 |
| 템플릿 준수 | 5점 | 글 유형에 맞는 템플릿 구조 따름 |

### 4. 경험 밀도 (20점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 경험 요소 수 | 10점 | 실제 사례/현장 변수/고객 질문/비교 상황/수치 (최소 3개) |
| AI 냄새 제거 | 5점 | 금지 표현 완전 제거 |
| 구어체 혼합 | 5점 | 10~20% 자연스러운 구어체 |

### 5. SEO (15점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 키워드 배치 | 5점 | 제목+첫문단+소제목 1개 이상에 자연 배치 |
| LSI 키워드 | 5점 | 연관 키워드 2개 이상 자연 삽입 |
| 스마트블록 대응 | 5점 | 경험성 요소 (현장 디테일/수치/Before·After) |

### 6. CTA (10점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 광고 느낌 없음 | 4점 | 자연스러운 유도 |
| 행동 유도 명확 | 3점 | 구체적 다음 행동 제안 |
| 브랜드 강점 연결 | 3점 | 무료실측/리뷰 등 자연스러운 신뢰 강화 |

# ENGINE S — SERIES STORY (시리즈 스토리 템플릿)

> 정보성 글(ENGINE 1~7)과 완전히 다른 포맷. 고객 스토리로 "다음 편이 궁금해지는" 연속물을 만든다.

## S-1. 시리즈 구조 (매 편 공통)

```
[1] 도입부 — 감정 직격
    고객의 첫 마디 인용 → 독자 "나도 저런데!" 공감
[2] 전개 — 현장 디테일  
    실측/진단/발견 과정을 생생하게 서술 (전문가 느낌)
[3] 반전 — 예상 밖 발견
    처음 의도와 다른 방향으로 전개 (화장실문→전체교체 등)
[4] 클리프행어 — 미완결 종료
    "다음 편에서는~" 으로 궁금증만 남기고 끊기
    ★ 결론/정리/요약 절대 금지 (마지막 편 제외)
```

## S-2. 시리즈 제목 규칙
- **①②③ 또는 EP.1/EP.2** 반드시 포함
- 29자 내외
- 키워드 자연 포함 (정보글만큼 앞배치 강제 아님)
- 예: "화장실문 때문에 방문교체 전체를 결심한 고객님 사연 ①"

## S-3. 시리즈 문체
- 구어체 **25% 이상** (정보글 15%보다 높게)
- 고객 대화체 **3회 이상** (큰따옴표 인용)
- 시점: 담당 매니저(문장군) 시점 → 독자는 따라가는 느낌
- 문단 길이: **3줄 이내** (스마트폰 가독성)

## S-4. 시리즈 CTA
```
1순위: "다음 편도 꼭 봐주세요" (시리즈 연결)
2순위: 무료 실측 예약 유도 (부담 없이)
★ 기존 다음 편이 있으면 하단에 링크 삽입
```

## S-5. 시리즈 채점 기준 (100점)

| 항목 | 배점 | 기준 |
|------|------|------|
| 제목 | 10 | 키워드 포함 + ①/EP.N 표시 + 29자 |
| 도입부 (공감) | 15 | 고객 첫 마디 인용 + 독자 공감 |
| 현장 밀도 (전문성) | 20 | 실측 디테일, 현장 변수, 전문 용어 |
| 반전과 확장 | 20 | 예상→반전 구조 자연스러움 |
| 구어체 비율 | 15 | 25% 이상 + 대화체 3회 |
| 시리즈 연결성 | 10 | 클리프행어 궁금증 유발 + 미완결 |
| CTA | 10 | 다음 편 기대 + 예약 유도 |

# 운영 원칙

## 핵심 철학

좋은 블로그는 "잘 쓴 글"이 아니라:

```
클릭되는 글 + 끝까지 읽히는 글 + 신뢰가 생기는 글
```

이 스킬은 **작문보다 "독자 행동 설계"를 우선**한다.

## 실행 규칙

- 주제만 받아도 ENGINE 1~7 자동 실행. 추가 질문 최소화.
- 업종/플랫폼 불명확 시 → 네이버 블로그 + 일반 정보성으로 작성 후 안내.
- "제목만" → ENGINE 1~2만 실행.
- "구조만" → ENGINE 1~3만 실행.
