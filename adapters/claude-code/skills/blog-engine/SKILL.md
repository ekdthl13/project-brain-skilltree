# BLOG ENGINE v4.1.0

한국형 블로그 콘텐츠를 **검색 의도 → 클릭 → 체류 → 신뢰 → CTA** 흐름으로 설계하는 실행 스킬이다.
상세 엔진 규칙은 필요할 때만 [REFERENCES.md](REFERENCES.md)를 읽고, 글 유형 템플릿은 [TEMPLATES.md](TEMPLATES.md)를 읽는다.
최종 제출 전에는 [CHECKLIST.md](CHECKLIST.md)를 통과해야 한다.

## Core Contract

블로그엔진은 주제만 받아도 기본값으로 실행한다. 질문은 최소화한다.

기본값:
- 플랫폼: 네이버 블로그
- 톤: 친근한 전문가
- 분량: 1,500~2,500자
- 목표 행동: 저장, 댓글, 문의, 내부링크 중 글 목적에 맞는 1개
- 품질 기준: 100점 만점, 85점 미만이면 수정 후 재채점

## Reference Loading

| 필요 상황 | 읽을 파일 |
|-----------|-----------|
| 글 유형별 세부 구조가 필요함 | [TEMPLATES.md](TEMPLATES.md) |
| 엔진별 상세 규칙, 예시, 채점표가 필요함 | [REFERENCES.md](REFERENCES.md) |
| 최종 검수 또는 Hard Fail 확인 | [CHECKLIST.md](CHECKLIST.md) |
| 브랜드/프로젝트 고유 규칙 확인 | 프로젝트 `AGENTS.md`, `BRAND_CONTEXT.md`, `CONTENT_PLAN.md`, `POSTING_REGISTRY.md` |

## Input Rule

필수 입력은 주제/키워드 하나다. 나머지는 문맥과 프로젝트 문서에서 추론한다.

| 항목 | 기본 처리 |
|------|-----------|
| 주제/키워드 | 필수 |
| 업종 | 자동 추론, 문서가 있으면 문서 우선 |
| 플랫폼 | 네이버 블로그 기본 |
| 브랜드 톤 | `BRAND_CONTEXT.md` 우선, 없으면 친근한 전문가 |
| 타겟 독자 | 검색 의도에서 추론 |
| CTA | 글 목적에 맞게 선택 |
| 참고자료 | URL/메모/기존 글이 있으면 반영 |

## Mode Router

| 모드 | 트리거 | 실행 범위 |
|------|--------|-----------|
| `FULL` | 기본, "블로그 써줘" | 전체 글 + 품질 채점 |
| `TITLE` | "제목만", "제목 뽑아줘" | 검색 의도 + 제목 후보 5개 |
| `STRUCTURE` | "구조만", "뼈대만" | 검색 의도 + 글 구조 + CTA 위치 |
| `REWRITE` | "다시 써줘" + 기존 글 | 기존 글 문제 진단 + 수정 본문 + 채점 |
| `SERIES` | "시리즈", "연재", "다음 편" | 시리즈 스토리 구조 + 클리프행어 |

## Execution Flow

1. **Intent**: 왜 검색했는지, 검색자 유형, 검색 단계, 감정, Pain Point를 분석한다.
2. **Hook**: 제목 후보 5개와 썸네일 카피 3개를 만든다.
3. **Structure**: 글 유형 템플릿을 선택하고 체류 구조를 잡는다.
4. **Writing**: 모바일 가독성, 경험 밀도, 구어체 리듬으로 본문을 작성한다.
5. **SEO**: 핵심 키워드, LSI, 내부링크, 스마트블록 대응을 반영한다.
6. **Conversion**: 광고처럼 보이지 않는 CTA를 배치한다.
7. **Quality**: 100점 기준으로 채점하고 85점 미만이면 수정 후 재채점한다.

## Template Selection

`CONTENT_PLAN.md`에 템플릿 컬럼이 있으면 그 값을 따른다. 없으면 아래 기준으로 고른다.

| 글 유형 | 템플릿 |
|---------|--------|
| 정보성 / 제품가이드 | A |
| 비교가이드 | B |
| 시공사례 / 지역 후기 | C |
| Q&A / 노하우 | D |
| 가격가이드 | E |
| 브랜드스토리 | F |
| 시리즈 스토리 | S |

템플릿 상세 구조는 [TEMPLATES.md](TEMPLATES.md)에서 해당 템플릿만 읽는다.

## Quality Gate

점수 기준:
- 95~100: 즉시 발행 가능
- 85~94: 발행 가능, 미세 조정 권장
- 75~84: 자동 수정 후 재채점
- 74 이하: 구조 재설계

Hard Fail:
- 검색 의도 분석 없이 본문 작성
- 제목 후보 5개 누락
- 금지 도입부 사용
- 경험 밀도 없이 일반론만 반복
- 근거 없는 통계 생성
- 품질 채점 누락

최종 출력 전 [CHECKLIST.md](CHECKLIST.md)를 확인한다.

## Minimal Output

이 스킬이 성공한 것으로 보려면 최소한 아래 산출물이 있어야 한다.

`FULL`:
- 제목 후보 5개와 추천 제목
- 검색 의도 분석
- 썸네일 카피 3개
- 완성 본문
- 자연스러운 CTA
- 내부링크 위치 또는 후보
- 해시태그 5~10개
- 품질 채점 총점과 미달 항목

부분 모드:
- `TITLE`: 제목 후보 5개, 추천 제목, 추천 이유
- `STRUCTURE`: 검색 의도, 글 구조, 소제목, CTA 위치
- `REWRITE`: 기존 글 문제점, 개선 방향, 수정 본문, 품질 채점
- `SERIES`: 시리즈 번호, 감정 도입, 현장 디테일, 클리프행어, 다음 편 CTA

## Operating Rules

- 주제만 받아도 실행한다. 추가 질문은 결과 품질을 크게 바꿀 때만 한다.
- 프로젝트 문서의 브랜드 톤과 금지 표현을 전역 스킬보다 우선한다.
- `POSTING_REGISTRY.md`가 있으면 중복 소재 여부와 등록 안내를 포함한다.
- 본문 안에 해시태그를 섞지 않는다. 해시태그는 태그란 입력용으로 분리한다.
- 이미지가 필요하면 `[사진: 설명]` 태그로 위치와 촬영 의도를 표시한다.
- 모든 스킬은 [CORE_PRINCIPLES.md](../CORE_PRINCIPLES.md)의 원칙에 종속된다.
