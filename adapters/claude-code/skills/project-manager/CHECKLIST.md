# 총괄매니저 CHECKLIST

> 총괄매니저 세션 검수표다. 긴 예시는 `REFERENCES.md`, 실행 절차는 `SKILL.md`를 따른다.

## Hard Fail

- [ ] `_context.md`를 읽지 않고 현재 상태를 단정하지 않는다.
- [ ] 검수 통과 후 기록 업데이트 없이 다음 오더를 만들지 않는다.
- [ ] 작업자 완료 보고만 믿지 않고 핵심 파일 또는 결과물을 직접 확인한다.
- [ ] 장기 결정은 `DECISION_LOG.md` 기록 여부를 판단한다.
- [ ] `_context.md`는 30줄 이내를 유지한다.
- [ ] 복잡 오더에 전체 코드 본문을 넣지 않는다.
- [ ] Phase 경계에서 사용자 로컬 확인 없이 다음 Phase 오더를 발행하지 않는다.

## 시작 체크

- [ ] `GEMINI.md` 또는 프로젝트 에이전트 지침을 확인했다.
- [ ] `DECISION_LOG.md`의 장기 결정과 문서 우선순위를 확인했다.
- [ ] `_context.md`의 현재 상태, 최근 완료, 다음 할 일을 확인했다.
- [ ] 진행 중인 `_order.md` 또는 `_playbook.md` 결과가 있는지 확인했다.
- [ ] `_audit_*.md` 미해결 위생 항목이 있으면 위생 정리 모드로 전환했다.

## 검수 체크

- [ ] 스코프 준수
- [ ] 금지 영역 보호
- [ ] 디자인/아키텍처/문서 패턴 일관성
- [ ] 완료 기준 충족
- [ ] 핵심 파일 또는 결과물 직접 확인

## 오더 체크

- [ ] 목표와 완료 기준이 명확하다.
- [ ] 참조 파일/패턴을 지정했다.
- [ ] 금지 영역을 명시했다.
- [ ] 150줄 이내다.
- [ ] 참조 파일이 있으면 전체 코드 본문을 넣지 않았다.
- [ ] `_order.md` 또는 `_playbook.md` 현재 슬롯을 덮어쓰기 전에 완료본 archive 여부를 확인했다.
- [ ] 작업 결과 기록 위치를 명시했다.

## 기록 체크

- [ ] `_context.md` 최근 완료/다음 할 일을 갱신했다.
- [ ] `PROJECT_TASKS.md` 상태 갱신 필요 여부를 판단했다.
- [ ] `DECISION_LOG.md` 기록 필요 여부를 판단했다.
- [ ] 실패 또는 반려가 있으면 복구 상태를 남겼다.
