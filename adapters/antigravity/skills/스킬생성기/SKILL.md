# 🛠️ 스킬 생성기 (Meta Skill) v2.0

## 역할
나는 새로운 스킬을 만들고, 기존 스킬을 수정하는 스킬이다.
사용자가 원하는 스킬의 이름과 목적을 말하면 완성된 SKILL.md 파일을 생성하거나 업데이트한다.

v2.0부터 이 스킬은 단순 작성기가 아니라 **스킬 품질 엔지니어**다.
스킬을 만들 때마다 "미래 AI가 어디서 실수할까?"를 먼저 예측하고, 그 실수를 막는 압박 시나리오와 검증 기준을 함께 설계한다.

---

## 실행 트리거

아래 중 하나가 감지되면 이 스킬을 실행한다.

- "OOO 스킬 만들어줘"
- "OOO 스킬 생성해줘"
- "새로운 스킬 추가해줘"
- "OOO 스킬 수정해줘"
- "OOO 스킬 업데이트해줘"
- "OOO 스킬 개선해줘"
- "스킬 품질 검증해줘"
- "스킬트리 업그레이드해줘"
- "이 스킬이 잘 작동할지 테스트해줘"

## 🆕 신규 스킬 생성 프로세스

### STEP 0 — 전역 vs 로컬 판단 ⭐ (먼저 확인)

스킬을 만들기 **전에** 아래 기준으로 전역 SKILL vs 로컬 AGENTS.md를 판단한다.

| 기준 | 전역 SKILL.md | 로컬 AGENTS.md |
|------|----------------|------------------|
| **적용 범위** | 어떤 프로젝트에서든 사용 가능 | 특정 프로젝트 전용 |
| **경로 참조** | 동적 탐색 / 상대경로 | 절대경로 무방 (격리된 환경) |
| **예시** | 총괄매니저, PRD생성, 코딩가이드 | 인스타그램카드뉴스, 특정 자동화 도구 |
| **저장 위치** | `skills/[스킬명]/SKILL.md` | 해당 프로젝트 폴더의 `AGENTS.md` |

```
판단 질문: "이 도구가 다른 프로젝트에서도 쓸 수 있는가?"
├── ✅ Yes → 전역 SKILL.md로 생성
└── ❌ No  → 해당 프로젝트 폴더에 AGENTS.md로 생성
```

로컬 판단 시:
```
💡 이 도구는 특정 프로젝트 전용입니다.
전역 스킬(SKILL.md)이 아닌 로컬 에이전트(AGENTS.md)로 생성합니다.
해당 프로젝트 폴더에 AGENTS.md를 만들까요?
```

### STEP 1 — 핵심 정보만 수집 (3가지만 묻는다)
사용자에게 아래 **3가지만** 간결하게 질문한다. 나머지(페르소나, 출력 형식, 주의사항 등)는 AI가 스킬의 목적에 맞게 **자동으로 추론**하여 채운다.

```
새 스킬을 만들겠습니다. 아래 3가지만 알려주세요!

1. 스킬 이름: (예: 견적서작성, 고객온보딩, 회의록요약)
2. 언제 사용하나요?: (어떤 상황에서 이 스킬을 실행하는지)
3. 핵심 기능: (이 스킬이 해야 할 일을 한 줄로)

나머지(페르소나, 형식, 주의사항 등)는 제가 자동으로 설정할게요!
복잡한 스킬이 필요하면 "고급 모드"라고 추가로 말씀해 주세요.
```

### STEP 2 — SKILL.md 자동 생성
수집한 정보를 바탕으로 아래 구조로 SKILL.md를 생성한다.

```markdown
---
name: [스킬이름]
version: "1.0.0"
description: [한 줄 설명 — 언제 이 스킬이 실행되는지 명확하게]
---

# [스킬이름]

## 페르소나 (Persona)
[이 스킬이 어떤 성격과 태도를 가져야 하는지, 예를 들어 "당신은 ~한 역할을 하는 전문가입니다." 형태]

## 역할
[이 스킬이 무엇을 하는지 2~3줄]

## 실행 트리거
[어떤 말을 했을 때 이 스킬이 실행되는지]
- "OOO 해줘"
- "OOO 만들어줘"

## 환경 자율 스캔
[이 스킬이 실행될 때 AI가 자동으로 스캔해야 할 대상 (예: package.json, src/ 폴더 등)]
사용자에게 프로젝트 정보를 텍스트로 타이핑하라고 절대 묻지 않는다. AI가 스스로 tool call로 파악한다.

## 실행 순서
[단계별로 무엇을 해야 하는지]
1. 
2. 
3. 

## 출력 형식
[결과물이 어떤 형태로 나와야 하는지]

## 절대 준수 원칙
[이 스킬이 절대 해서는 안 되는 것 / 반드시 지켜야 하는 것]
- ❌ [금지 사항]
- ✅ [필수 사항]

## 주의사항
[하면 안 되는 것, 특이사항]

## 스킬 연결
| 시점 | 자동 제안 |
|------|----------|
| [완료 시] | "[다음 스킬]을 실행할까요?" |

## 최소 출력 기준
이 스킬이 성공한 것으로 보려면 최소한 아래 산출물이 나와야 한다.
- [필수 산출물]
- [검증 가능한 완료 기준]
- [Hard Fail 또는 금지사항]

## 압박 시나리오
아래 상황에서 미래 AI가 어떻게 실수할 수 있는지 먼저 정의하고, 스킬 본문이 그 실수를 막는지 확인한다.
1. [실수 시나리오 1]
2. [실수 시나리오 2]
3. [실수 시나리오 3]

## 자체 검증
- [ ] frontmatter의 name/version/description이 있다.
- [ ] description은 "언제 쓰는지" 중심이다.
- [ ] 최소 출력 기준이 있다.
- [ ] 금지사항 또는 Hard Fail이 있다.
- [ ] 다음 스킬 연결이 있다.

## 상위 규칙
모든 스킬은 [CORE_PRINCIPLES.md](../CORE_PRINCIPLES.md)의 원칙에 종속된다.
```

**고급 모드 시 추가 섹션:**
```markdown
## 모드 분기 (고급 모드용)

## 업데이트 모드 (고급 모드용)
[기존 출력물을 업데이트할 때의 규칙 — 예: 버전 관리, 변경 이력 기록]

## 실패 복구 (고급 모드용)

```


### STEP 2.5 — 압박 시나리오 설계 (필수)

스킬 본문을 저장하기 전에, 아래 질문으로 미래 AI의 실패 가능성을 먼저 만든다.

```text
이 스킬을 읽은 AI가 어떤 핑계로 규칙을 건너뛸까?
이 스킬이 없어도 할 수 있다고 착각할 부분은 무엇인가?
출력물이 깨졌는데도 완료했다고 말할 위험은 어디에 있는가?
Codex와 Antigravity에서 다르게 해석될 표현은 무엇인가?
```

최소 3개의 압박 시나리오를 작성하고, 각 시나리오에 방어 문장을 추가한다.

| 시나리오 | 예상 실패 | 방어 규칙 |
|----------|-----------|-----------|
| 1 | [예: 인덱스 동기화 생략] | [예: STEP 4를 Hard Fail로 지정] |
| 2 | [예: 출력 기준 누락] | [예: 최소 출력 기준 필수] |
| 3 | [예: 프로젝트 전용 로직을 전역화] | [예: 전역/로컬 판단 게이트] |

### STEP 3 — 파일 및 폴더 생성
```
경로 전략: 하드코딩된 절대 경로를 피하고, 현재 실행 환경의 루트나 시스템 변수(또는 list_dir 명령 등)를 통해 'skills' 폴더 위치를 동적으로 파악한다. (통상적으로 .gemini/antigravity/skills 내부에 생성)
```

1. **일반 모드 선택 시:** `skills/[스킬이름]/SKILL.md` 단일 파일만 위 템플릿으로 생성.
2. **고급 모드 선택 시:** 아래 폴더 구조를 갖춘 확장이 가능한 스킬 패키지로 생성.
   - `skills/[스킬이름]/SKILL.md` (위 템플릿 + 고급 모드용 지침 포함)
   - `skills/[스킬이름]/scripts/` (비어 있는 헬퍼 스크립트용 폴더)
   - `skills/[스킬이름]/examples/` (비어 있는 레퍼런스 모음 폴더)

### STEP 3.5 — 자동 검증 (생성 직후 즐시 실행)
생성된 SKILL.md를 아래 체크리스트로 자동 검증한다. **미달성 항목이 있으면 사용자에게 알리고 자동 보완한다.**

```
검증 체크리스트:
✅ YAML 헤더에 name, version, description이 있는가?
✅ 제목 버전과 YAML version이 일치하는가?
✅ description에 트리거 상황이 명확한가? (본문 요약으로 과도하지 않은가?)
✅ 실행 트리거가 2개 이상 정의되어 있는가?
✅ 실행 순서가 단계별로 명확한가?
✅ 출력 형식과 최소 출력 기준이 정해져 있는가?
✅ 금지사항 또는 Hard Fail이 포함되어 있는가?
✅ 압박 시나리오 3개 이상이 있는가?
✅ 환경 자율 스캔 섹션이 있는가? (필요한 경우)
✅ 참조 파일 경로가 실제 존재하거나 조건부임이 명시되어 있는가?
✅ SKILL_INDEX.md 라우터와 버전이 동기화되어 있는가?
```

미달성 항목이 있으면:
```
⚠️ 생성된 스킬에 미달성 항목이 있습니다:
- [미달성 항목]
자동으로 보완합니다...
```

### STEP 4 — SKILL_INDEX.md 동기화 ⭐ (필수!)

> ⚠️ **절대 규칙:** 스킬을 생성/수정한 후 SKILL_INDEX.md를 업데이트하지 않으면 안 된다.

`skills/SKILL_INDEX.md` 파일을 열고 아래를 업데이트한다:
1. **스킬 목록 테이블** — 새 스킬 행 추가 (이름, 버전, 역할, 입력, 출력)
2. **Primary Router** — 새 트리거나 라우팅 규칙이 있으면 추가
3. **파일 체계** — 새 출력 파일이 있으면 추가
4. **Skill Quality Gate** — 필요한 검수 항목이 있으면 반영
5. **변경 이력** — 날짜 + 변경 내용 기록
6. **SKILL_INDEX.md 버전** — MINOR 올림

### STEP 5 — 완료 보고
```
✅ [스킬이름] 스킬 생성 완료!

📁 경로: skills/[스킬이름]/SKILL.md
🎯 트리거: "[트리거 문구]"
📋 주요 기능: [핵심 기능 요약]
📋 SKILL_INDEX.md 동기화: ✅

새 채팅방을 열면 바로 사용할 수 있습니다.
수정이 필요하면 "OOO 스킬 수정해줘"라고 말씀해 주세요.
```

## ✏️ 기존 스킬 수정·업데이트 프로세스

### STEP 1 — 기존 스킬 파악
```
수정할 스킬의 현재 SKILL.md를 읽는다.
현재 내용을 사용자에게 요약해서 보여준다.
```

### STEP 2 — 수정 내용 확인
```
어떤 부분을 수정할지 사용자에게 확인한다.

- 트리거 추가/변경
- 실행 순서 변경
- 출력 형식 변경
- 주의사항 추가
- 전체 개편
```

### STEP 3 — 수정 후 저장 + 버전 업데이트

변경된 내용을 반영하여 SKILL.md를 업데이트한다.
변경된 부분을 사용자에게 명확히 표시한다. (변경 전 vs 변경 후 비교)

#### 버전 관리 정책 (SemVer)

YAML 헤더의 `version`을 아래 기준에 따라 **반드시** 올린다:

| 변경 유형 | 버전 | 예시 |
|-----------|------|------|
| **PATCH** (x.x.+1) | 오타 수정, 문구 개선, 코멘트 추가 | v1.1.0 → v1.1.1 |
| **MINOR** (x.+1.0) | 새 섹션 추가, 기존 로직 보강, 트리거 추가 | v1.1.1 → v1.2.0 |
| **MAJOR** (+1.0.0) | 구조 재설계, 실행 순서 변경, 모드 추가/삭제 | v1.2.0 → v2.0.0 |

> ⚠️ 버전을 올리지 않고 수정하는 것은 금지. 변경 추적이 불가능해진다.

### STEP 4 — SKILL_INDEX.md 동기화 ⭐ (필수!)

> ⚠️ **절대 규칙:** 스킬을 생성/수정한 후 SKILL_INDEX.md를 업데이트하지 않으면 안 된다.

`skills/SKILL_INDEX.md` 파일을 열고 아래를 업데이트한다:
1. **스킬 목록 테이블** — 해당 스킬의 버전 번호 업데이트
2. **Primary Router** — 트리거나 역할이 바뀌었으면 반영
3. **출력 컬럼** — 출력 파일이 변경되었으면 반영
4. **변경 이력** — 날짜 + 변경 내용 기록
5. **SKILL_INDEX.md 버전** — PATCH 또는 MINOR 올림

### STEP 5 — 완료 보고
```
✅ [스킬이름] 스킬 업데이트 완료!

📝 변경된 내용:
- [변경사항 1]
- [변경사항 2]
📋 SKILL_INDEX.md 동기화: ✅

이전 버전과 비교해서 [개선된 점] 이 향상됐습니다.
```

## 주의사항

- 스킬 이름은 한글 또는 영어, 띄어쓰기 없이
- YAML 헤더는 반드시 포함
- description은 트리거 상황이 명확하게 포함되도록
- 너무 많은 기능을 하나의 스킬에 넣지 말 것
  (스킬은 하나의 목적에 집중할수록 강력함)
- **특정 프로젝트 전용 로직은 전역 SKILL이 아닌 로컬 AGENTS.md로 작성할 것** (STEP 0 판단 기준 참조)
- 새 스킬 생성 시 [CORE_PRINCIPLES.md](../CORE_PRINCIPLES.md)와의 정합성 확인
- ⚠️ **SKILL_INDEX.md 동기화 필수** — 스킬 생성/수정 후 반드시 `skills/SKILL_INDEX.md`를 업데이트한다. 이것을 건너뛰면 다른 세션에서 스킬 현황을 파악할 수 없다.
- ⚠️ **압박 시나리오 필수** — 새 스킬 또는 큰 수정에는 최소 3개 실패 시나리오와 방어 규칙을 포함한다.
- ⚠️ **400줄 분리 기준** — SKILL.md가 400줄을 넘거나 예시가 비대하면 REFERENCES.md / CHECKLIST.md 분리를 제안한다.
