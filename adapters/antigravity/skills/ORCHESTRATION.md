# Multi-Model Orchestration Protocol

> Project Brain Skilltree는 단일 모델에 모든 판단과 실행을 맡기지 않는다.
> 고추론 모델은 판단하고, 저비용 모델은 실행한다.

## Purpose

이 문서는 Project Brain Skilltree의 모델 역할 분리 원칙을 공식화한다.
총괄매니저의 모델 추천, 코딩가이드의 작업 실행, 암행어사/출시점검의 검수 루프가 같은 기준을 따르도록 만든다.

## Core Formula

```text
두뇌 = 총괄매니저 + 오피스아워 + PRD생성 + 전략 검수
손   = 코딩가이드 실행 + 반복 콘텐츠 생성
눈   = 암행어사 + 출시점검 + 총괄 검수

파일 = 기억 (_context.md, _order.md, DECISION_LOG.md, PROJECT_TASKS.md)
사용자 = 사장 (최종 결정, 도메인 경험, 비즈니스 판단)
```

## Operating Loop

```text
사용자
  ↓
총괄 세션
  - _context.md, _order.md, DECISION_LOG.md 확인
  - 이전 결과 검수
  - 다음 작업 판단
  - _order.md 또는 _playbook.md 생성
  - _context.md 업데이트
  ↓
작업 세션
  - _order.md 해석
  - 에스컬레이션 조건 확인
  - 기존 패턴 분석
  - 점진적 구현
  - 자체 검증
  - _order.md 작업 결과 기록
  ↓
총괄 검수 세션
  - 작업 결과 확인
  - 핵심 파일 직접 확인
  - 완료 기준 판정
  - 검수 → 기록 → 다음 오더 순서 준수
```

## Model Tier Guide

| Tier | 능력 수준 | 주요 용도 | 예시 |
|------|----------|----------|------|
| T1 전략 | 최상위 추론 | 오피스아워, PRD, 전략 모드, 전문가 렌즈 | top reasoning models |
| T2 판단 | 깊은 추론 | 총괄 계획/검수, 디자인시스템, 출시점검 | balanced high reasoning models |
| T3 실행 | 균형형 코드/작성 | 코딩가이드 중간 구현, 블로그/인스타 작업 | standard coding/writing models |
| T4 단순 | 빠른 저비용 | 단순 수정, 포맷팅, 리네이밍, 반복 작업 | fast low-cost models |

모델명은 환경마다 바뀔 수 있다. 이 문서는 특정 공급자보다 능력 등급을 기준으로 판단한다.

## Order-Level Model Selection

```text
아키텍처 결정이 포함되는가? ─YES→ T1
새로운 패턴 도입인가?       ─YES→ T2
기존 패턴 따라 구현인가?    ─YES→ T3
파일 1~2개 단순 수정인가?   ─YES→ T4

보정 규칙:
- 원인 불명 디버깅이면 한 단계 올린다.
- 4파일 이상 동시 수정이면 한 단계 올린다.
- 반복/템플릿 작업이면 한 단계 내린다.
```

## Cost Discipline

1. 판단은 비싸게, 실행은 싸게 한다.
2. T1은 전략, 기획, 고위험 검수에 우선 사용한다.
3. 대부분의 구현은 좋은 오더가 있으면 T3/T4로 충분해야 한다.
4. 오더가 구체적일수록 더 낮은 티어 모델로도 정확한 결과가 나온다.
5. 오더가 모호하면 높은 티어 모델을 써도 스코프 크립과 재작업이 늘어난다.

## Handoff Protocol

### 총괄 → 작업자

| 단계 | 행동 | 파일 |
|------|------|------|
| 1 | 총괄이 오더 생성 | `_order.md` 또는 `_playbook.md` |
| 2 | 추천 모델 명시 | 오더의 `추천 모델` 필드 |
| 3 | 금지 영역 명시 | 오더의 `금지` 섹션 |
| 4 | 세션 종료 전 현재 상태 갱신 | `_context.md` |
| 5 | 사용자가 새 작업 세션에서 오더 실행 | 작업자 세션 |

### 작업자 → 총괄

| 단계 | 행동 | 파일 |
|------|------|------|
| 1 | 구현과 자체 검증 완료 | 소스 코드 |
| 2 | 작업 결과 기록 | `_order.md` |
| 3 | 상태 표기 | ✅ 완료 / ⚠️ 부분 완료 / 🟡 반려 / 🔴 불가 |
| 4 | 사용자가 총괄 세션으로 돌아와 검수 요청 | 총괄 세션 |

### 에스컬레이션 상태

| 상태 | 의미 | 다음 행동 |
|------|------|----------|
| ✅ 완료 | 정상 완료 | 총괄 검수 후 기록 업데이트 |
| ⚠️ 부분 완료 | 완료분과 미완료분이 분리됨 | 미완료분 새 오더 |
| 🟡 반려 | 오더 모호 또는 범위 초과 | 오더 재발행 또는 플레이북 변환 |
| 🔴 불가 | 현재 조건에서 완료 기준 달성 불가 | 대안 선택 후 새 오더 |
